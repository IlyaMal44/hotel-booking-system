# ADR 001. Отдельные приложения и multi-stage образы

## Контекст

Задание требует четыре самостоятельных Spring Boot-приложения. У Hotel и Booking своя H2. Возникает соблазн описать это одним «multi-stage» процессом.

## Решение

Репозиторий — Gradle multi-module:

- `eureka-server`, `api-gateway`, `hotel-service`, `booking-service` запускаются отдельными процессами;
- `common` не является сервисом и не содержит бизнес-логики. Там только контракт ошибки, проверка дат и разбор HMAC-ключа, чтобы сервисы не копировали эти три вещи.

Multi-stage используется только в `Dockerfile`: стадия `build` с JDK собирает jar нужного модуля, стадия runtime копирует его в образ с JRE. `docker compose` поднимает четыре контейнера. Образ не склеивает сервисы в один процесс.

У Eureka и Gateway нет H2. Им некуда класть отели и брони, а пустая база ничего не доказывает.

## Следствия

Сервис можно перезапустить, не трогая остальные. Данные соседа при этом не откатываются: поэтому отмена брони — отдельный вызов `release`, а не общий rollback.
